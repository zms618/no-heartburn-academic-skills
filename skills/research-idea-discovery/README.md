# Research Idea Discovery

[简体中文](README.md) | [English](README.en.md) | [科研插件合集总览](../../README.md)

**Evidence-Driven Research Idea Discovery, Feasibility Validation & Scientific Review**

一款面向 ChatGPT 网页端的科研问题发现与验证插件。它帮助研究者从研究方向出发，梳理可检验的问题，查证相关工作与证据，再用可行性检查和审稿人式压力测试判断下一步应继续、修改、转向还是停止。

> **在 ChatGPT 网页端上传 ZIP 安装使用，不消耗 Codex 专用额度。**
>
> **不只生成 Idea：先把问题说清，再检查证据、近邻、可行性和最危险的反方质疑。**

当前版本 **v4.0.19** 将流程重心放在研究问题形成、自主证据审查与压力测试上。它不承诺找到全新方向或保证论文录用；证据不足时会明确提出需要补查的内容。

## v4.0.19：自主研究验证与压力测试

针对每个候选方向，主 Skill 要求依次检查：

1. **形成研究问题**：明确研究对象、目标和问题边界。
2. **审查证据置信度**：区分论文或数据中已核实的事实、合理判断与待验证假设。
3. **排查近邻冲突**：检查近期工作、最相似方法和术语重叠，避免把已有方法改名当作创新。
4. **验证问题成立**：确认问题是否真实、有研究价值，并检查反例与替代解释。
5. **模拟审稿人压力测试**：质疑研究空白、机制主张、实验区分能力、团队可执行性和领域价值。
6. **评估可行性**：核查数据、计算资源、复现条件与评测协议；无法验证时降低结论强度或暂停。
7. **给出研究决策**：结合证据提出 GO、CONDITIONAL GO、REFRAME 或 STOP 等下一步建议。
8. **通过判断后再探索方法**：避免先堆方法模块、后寻找研究动机。

当新颖性或可行性证据不足时，插件可以整理缺口并生成可复制到 ChatGPT Deep Research 的调研提示词，由用户手动启动后再带回结果。方向决策可累计记录，减少重复讨论；它不会声称已自动启动云端调研或真实实验。

## 适合什么场景？

- 我有一个研究方向，但还不清楚值得研究的具体问题。
- 我已有一个 Idea，想先找最危险的近邻工作并接受严格质疑。
- 我需要判断数据、基线、算力与评估协议是否支持一次可信的验证。
- 我想把已有实验和主张整理成能经受审稿人追问的研究决策。
- 我暂时没有足够证据，希望知道该补查什么，或是否应停止当前方向。

插件包含主研究决策 Skill、文献与数据调查、问题验证、机制必要性检查、审稿压力测试、执行计划和决策记录等辅助 Skills。联网检索、文件处理和工具访问取决于 ChatGPT 当前账号和权限；配套 Python 脚本只在支持本地执行的环境中运行。

## 核心原则

- **问题先于方法**：热门技术迁移只能形成假设，不能自动构成研究动机。
- **证据先于自信**：不把检索线索、计划中的实验或结构检查说成已验证结果。
- **近邻必须认真查**：比较问题、机制、训练目标和评估协议，而非只看标题关键词。
- **先找反方解释**：优先设计能区分主张与替代解释的实验。
- **允许停止**：如果证据不支持投入资源，就明确建议补查、改题或停止。

## 在 ChatGPT 网页端上传 ZIP 并安装

推荐直接上传已经整理好的插件包，无需通过 Plugin Creator 从源码重新创建。

[下载 Research Idea Discovery v4.0.19 插件 ZIP](../../downloads/research-idea-discovery-v4.0.19.zip)

1. 打开 ChatGPT 个人插件页面（可从头像/设置进入“插件”或“个人插件”，也可访问 [chatgpt.com/plugins?directoryTab=personal](https://chatgpt.com/plugins?directoryTab=personal)）。
2. 点击 **添加**，选择 **上传插件压缩包**。
3. 选择 `research-idea-discovery-v4.0.19.zip`，等待解析完成并按提示创建或安装。
4. 在个人插件列表确认插件已添加；新建对话后从工具/插件选择器中启用，再描述你的研究方向或当前问题。

界面文字可能随账号和产品版本略有不同。上传个人插件不会使其自动进入 ChatGPT 公共目录。联网检索等工具能力仍取决于 ChatGPT 当前账号和权限；压缩包里的 Python 脚本供支持本地执行的环境使用，ChatGPT 网页不会自动替你运行这些脚本。

如果当前账号没有 ZIP 上传入口，可从本仓库源码使用 Plugin Creator 创建；该备用方式需要由创建器读取 GitHub 源码并遵循本页列出的主 Skill、references 与辅助 Skills。

## 使用示例

**从研究方向发现候选问题**

> 我的方向是多模态领域泛化，目标是顶级计算机视觉会议。请从相关研究中的具体失败现象出发，寻找候选科学问题；调查可用数据和 Baseline，再严格审查研究动机、新颖性、机制必要性与验证成本。每一步区分已核实证据和待验证假设。

**审查已有 Idea**

> 请像严格审稿人一样评估这个 Idea。先找最危险的近邻工作，再判断研究问题是否真实、机制是否必要、简单替代方案能否达到同样效果，以及哪些实验最可能推翻我的主张。证据不足时请建议 REFINE、PIVOT、STOP 或继续调研。

**准备深度调研交接**

> 目前还没有足够强的候选。请总结已检索范围、淘汰的方案和关键证据缺口，生成一份可复制到 ChatGPT Deep Research 的定向调研提示词。不要声称你已自动启动 Deep Research。

## 可选本地工具

`scripts/` 提供文献检索元数据、数据集发现与样本检查、可行性卡片验证、研究工作流状态门、审稿/实验记录、候选 Idea 台账和 Deep Research 报告交接等工具。它们用于本地辅助与记录，不会替代论文全文核验或学术判断。部分本地数据源可能支持可选 API Key；网络访问、数据许可、凭据和实际实验执行都需要相应权限。

特别注意：`scripts/pilot_bridge.py` 只在显式传入 `--execute` 时运行用户指定的本地命令；默认是 `DRY_RUN`。执行前应先检查命令和工作目录。ChatGPT 网页不会替用户执行该脚本。

在本项目目录运行测试：

```bash
python -m unittest discover -s tests -v
```

使用各脚本的 `--help` 查看命令选项。不要把 Dry Run、空日志或仅有计划的实验记录表述为真实执行结果。

## 设计原则与边界

1. **可行性优先**：没有可信验证路径的构想不能包装成成熟方案。
2. **创新不等于加模块**：术语变化和模块组合不自动构成实质创新。
3. **先证明动机，再讲故事**：论证应由问题、机制和证据支撑。
4. **证据胜过自信**：明确标注已核验、推测和未验证内容。
5. **先尝试证伪**：优先设计可能推翻核心假设的实验。
6. **允许没有好 Idea**：证据不够时，说明不确定性并建议下一步。

该 Skill 不保证发现全新方向、完整覆盖文献或被任何会议录用。联网调查的广度取决于可用来源与工具；真实数据访问和 GPU 实验依赖授权及执行环境。所谓审稿角色是流程视角，不代表部署了多个独立模型。Deep Research 交接目前是提示词生成和用户手动回传，不会自动启动云端研究任务。

**目标不是说服你某个 Idea 很好，而是让它经得起反复质疑之后，仍然值得投入科研时间和资源。**
